Project-Level CMakeLists Details

Top CMakeLists Details

The CMakeLists file at the top of the project directory tree includes each of the third party libraries needed by the project and adds the src and test subdirectories.

The first few lines of code remove any duplicate entries from the TPL_DEPENDENCIES list, defined in the Dependency file, then go through each third party library in the list and run their associated .cmake file. Each of these files handle finding the package on the user's machine and adding the package's include directories to the search path. They also set some variables for later use.

list is used in this file with the REMOVE_DUPLICATES parameter. This command moves through the variable named after REMOVE_DUPLICATES, removing all copies of elements in the list. 

# Third party library dependencies
list(REMOVE_DUPLICATES PROJ_TPL_DEPENDENCIES)
foreach(PROJ_TPL ${PROJ_TPL_DEPENDENCIES})
    include(${MORIS_TPL_DIR}/${PROJ_TPL}.cmake)
endforeach()

The second portion of the file processes the CMakeLists in the source directory so that the project's library is built. Then, if MORIS_USE_TESTS and your project's build option has been selected, the test directory is also processed. 

# Add source directory
add_subdirectory(src)

# Add test directory
if(MORIS_USE_TESTS AND BUILD_PROJ)
    add_subdirectory(test)
endif()

Source-level CMakeLists Details

Header Section

The first section of the source-level CMakeLists.txt sets the project version, lists of the project's header files, and adds necessary moris directories to the search path. The project version is set to be used for version checking when users include moris in their own projects. 

# Set version
set(${PROJ}_VERSION ${MORIS_VERSION})

Header files are listed so that they can be added to an include directory when the project is installed. More information on installation can be found in Installation Section below. 

# List header files
set(HEADERS
    project_header_1.hpp
    ...
    project_header_n.hpp )

The last bit of code in this section lists the moris projects whose headers are needed by the current project. This list is then iterated through, adding the src directory of each moris project in the list to the search path so your project can find files from other moris projects. 

# List header dependencies
set(PROJ_INCLUDES
    ${MORIS_PROJECT_1}
    ...
    ${MORIS_PROJECT_N} )

foreach(PROJ_INCLUDE ${PROJ_INCLUDES})
    include_directories(../../${PROJ_INCLUDE}/src)
endforeach()

Config Files Section

The configuration file section first includes CMakePackageConfigHelpers, a CMake module that adds the configure_package_config_file and write_basic_package_version_file functions, among others. All functions included by this module are tools that aid in the creation of config files, discussed in Config. 

# Build *Config and *ConfigVersion files
include(CMakePackageConfigHelpers)

configure_package_config_file dereferences CMake variables and inserts important code into the config template file written in Config. First, it takes the name of the config template file (or path to it if applicable). The second argument is what the full path to the config file will be once the project has been built. After that, the INSTALL_DESTINATION for the config file is set. Lastly, PATH_VARS precedes a list of variables that will be referenced in the config file. This list can be added to as seen fit, but should at least contain the variables listed below. 

configure_package_config_file(
    ${PROJ}Config.cmake.in
    ${${PROJ}_CONFIG_BUILD_DIR}/${PROJ}Config.cmake
    INSTALL_DESTINATION ${CONFIG_INSTALL_DIR}/${PROJ}
    PATH_VARS LIB_INSTALL_DIR )

write_basic_package_version_file creates a file to be build alongside the config file which checks the project version and throws an error if it is not compatible with the version that the user requested. The first argument is what the full path to this file will be. After the VERSION parameter is the project's version (defined in Header Section). Then, COMPATIBILITY precedes the requirements that will be used when checking compatibility. AnyNewerVersion means that the version checker will accept any project version equal to or newer than the requested version. Other options for compatibility checking can be found in CMakeFunctions. 

write_basic_package_version_file(
    ${${PROJ}_CONFIG_BUILD_DIR}/${PROJ}ConfigVersion.cmake
    VERSION ${{PROJ}_VERSION}
    COMPATIBILITY AnyNewerVersion )

Installation Section

Package installation is important for down the line when external users want to download and use moris. After building moris, they will use @type{make install} to install moris in their third party library directory. This section will tell CMake which files to install and where to put them.

The first install command installs the Config and ConfigVersion files built in the previous section to the share/PROJ directory of the install tree. The second install command installs the list of header files created in the Header Section.

Like list, the install command has many different subcommands that define its behavior. Here, the FILES parameter is used to install individual files in the directory specified after DESTINATION. 

# Install *Config and *ConfigVersion files
install(FILES ${${PROJ}_CONFIG_BUILD_DIR}/${PROJ}Config.cmake 
    ${${PROJ}_CONFIG_BUILD_DIR}/${PROJ}ConfigVersion.cmake
    DESTINATION ${CONFIG_INSTALL_DIR}/${PROJ} )

# Install header files
install(FILES ${HEADERS}
    DESTINATION ${HEADER_INSTALL_DIR}/${PROJ} )

The next piece of code in this section installs the library and/or executable into lib/PROJ for libraries and bin/PROJ for executables. Then, it adds these targets to a group, PROJTargets.

install with the TARGETS subcommand installs the listed targets into a destination based on their types. Static libraries go to ARCHIVE_DESTINATION, shared libraries go to LIBRARY_DESTINATION, and executables go to RUNTIME_DESTINATION. The EXPORT parameter at the end groups the targets under the name that follows it. Recall that only targets which already exist should be included with this command. 

# Install library and executable
install(TARGETS ${PROJ}-lib ${PROJ}-exe
    ARCHIVE_DESTINATION ${LIB_INSTALL_DIR}/${PROJ}
    LIBRARY_DESTINATION ${LIB_INSTALL_DIR}/${PROJ}
    RUNTIME_DESTINATION ${EXE_INSTALL_DIR}/${PROJ}
    EXPORT ${PROJ}Targets )

The last part of the installation section exports the target group, creating another file that will be included by the Config file. Including this file will allow external projects to reference the exported moris targets. install with the EXPORT command takes the name of the group to export and then the DESTINATION path to export it to. The new file will have the name of the group, appended with .cmake. 

# Export library into *Targets file
install(EXPORT ${PROJ}Targets
    DESTINATION ${CONFIG_INSTALL_DIR}/${PROJ} )

Test-Level CMakeLists Details

The code in the test-level CMakeLists.txt is very similar to that in Adding Executables. The file includes needed directories, sets an output location for the test executable, creates the executable, links it to the appropriate libraries, and then enables it for running with CTest.

TEST_SOURCES, set at the top of the file, should be filled with all of the test source files. Make sure test_main.cpp is included in this list. It is the wrapper which is used to run all moris tests and can be found in any other project test directory. 

# List source files
set(TEST_SOURCES
    test_main.cpp
    my_test_1.cpp
    ...
    my_test_n.cpp )

TEST_INCLUDES lists all of the moris projects the test needs to include header files from. LNA, IOS, and COM will always be needed because of test_main.cpp. The next bit of code goes through each element in TEST_INCLUDES and includes that package's src directory. If any other directories need to be included, add an include_directories command under @type{List additional includes}. 

# List test includes
set(TEST_INCLUDES
    ${LNA}
    ${IOS}
    ${COM}
    ...
    ${MORIS_PROJECT} )

foreach(TEST_INCLUDE ${TEST_INCLUDES})
    include_directories(../../${TEST_INCLUDE}/src)
endforeach()

# List additional includes

After all necessary directories have been included, the TEST_DEPENDENCIES variable should be filled with libraries that the test needs to link to. Recall that these libraries are either the moris package name followed by -lib or a variable whose name is MORIS_TPL_LIBS where TPL is the name of the third party library or libraries (like ARMADILLO_EIGEN) to be linked. For tests COM-lib is always needed due to test_main.cpp. 

# List test dependencies
set(TEST_DEPENDENCIES
    ${COM}-lib
    ...
    ${MORIS_{TPL}_LIBS} )

The output path for the test is set with CMAKE_RUNTIME_OUTPUT_DIRECTORY and will appear in moris/projects/PROJ/test/bin unless made otherwise. 

# Set the output path for test
set(CMAKE_RUNTIME_OUTPUT_DIRECTORY ${CMAKE_CURRENT_BINARY_DIR}/${BIN})

add_executable will create a make target for PROJ-test.exe using TEST_SOURCES. Then, target_link_libraries links PROJ-test.exe to TEST_DEPENDENCIES. 

# Create executable
add_executable(${PROJ}-test${EXE_EXT} ${TEST_SOURCES})
target_link_libraries(${PROJ}-test${EXE_EXT} ${TEST_DEPENDENCIES})

Finally, the executable is marked as a test. The test can the be run with the commands @type{make test} or ctest in the command line. Further details will come tomorrow. Header Section

add_test takes the NAME parameter followed by the name the test will have in the output. The code that follows the COMMAND parameter is what will be run on the command line for this test when ctest or @type{make test} is called. If COMMAND is followed by the name of an executable CMake target, the executable will be run from wherever it is located. 

# Mark as test
add_test(NAME ${PROJ}-test
    COMMAND ${PROJ}-test${EXE_EXT} )
