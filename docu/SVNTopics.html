Why SVN?

This page discussion other SVN related topics, such as setting up a repository, and ends with a general comparison to CVS.

Introduction

This section assumes the project is hosted on thunderbird and named MORIS.

Installing the SVN Plug-In

To install the SVN plug-in in Eclipse,

  1. Open the Help menu and click on Install New Software.

  2. In the Work with: dropdown menu, select menu, select your version of Eclipse. For example, if you are working with Eclipse-Luna, select Luna - http://download.eclipse.org/releases/luna/.

    Note
    You may need to Add this.
  3. Expand the Collaboration section and select the Subversive SVN Team Provider plug-in.
  4. Click Next to review the Install Details.
  5. Click Next, accept the license terms, and click Finish. Eclipse will download all necessary files.
  6. You will be prompted to restart Eclipse, do so. You will now need to install an SVN Connector.
  7. Open the Window menu and click on Preferences.
  8. Expand the Team section and click on SVN. If you are working in Windows, the SVN folder can be expanded directly.

  9. Under the SVN Connector tab, click on Get Connector.

    Note
    If a connector is already listed, you need not install another. Skip the remainder of this guide.
    If this option does not appear, skip the remainder of this guide and attempt to checkout the code (see section: Checkout Using Eclipse). Here, Eclipse will automatically prompt you to download a Connector.
  10. Choose the latest version of SVN Kit by Polarion. Click Finish.
  11. Click Next to review the Details.
  12. Click Next and accept the license terms.
  13. Click Finish.

Initial Repository Setup

Creating the Repository

You need to have write access to /home/svnroot. Assuming you are currently in /home/svnroot on thunderbird, use the following command to create the project:

    svnadmin create MORIS

It is necessary to also run 

    chmod 775 -R MORIS

so that other users on thunderbird have the required write access to the repository when they commit. Other authentication options are available on a repository basis, but that seems unnecessary at present.

Importing an Existing Directory of Files to the Repository

This section assumes that you have a directory called testDir that contains files (and subdirectories with other files) that should be added (i.e. imported) to the repository.

If you are working on the same machine as the repository (on thunderbird) the files can be added by calling

  svn import -m "initial commit comment here" testDir file:///home/svnroot/MORIS

where you are also specifying an inline comment: initial commit comment here by calling -m. If the inline comment is omitted, a text editor will be automatically opened to prompt the user for a comment.

If you are working on another machine and would like to import to the repository on thunderbird, use the following command:

  svn import -m "initial commit comment here" \ 
  testDir svn+ssh://thunderbird.colorado.edu/home/svnroot/MORIS

Directories and Moving Files in Eclipse

Suppose a file main.C is in the moris directory and that you create and commit a new directory src and then moves main.C from moris into MORIS/src.

If you then right-click on src and commit, you will get an error mentioning committing both sides of the move. It is important to commit a higher directory (e.g., moris) so that both the deletion of the original position of main.C and the addition of it in src will be seen by the commit.

Committing Changes

To commit changes, in the project directory, enter the command:

  svn commit

This will bring up a text editor for comments associated with the commit. Alternatively, enter the command:

  svn commit -m "some comment"

This will NOT bring up a text editor for comments associated with the commit.

Updating to Latest revision of Files

To update the project, enter the command:

  svn update

Ignoring Directories or Files

To have svn ignore a particular directory, use the ‘svn propset’ function. For example, suppose you wish to have svn ignore the directory MORIS/bin.

Note
Once a directory is added to the svn:ignore list, it does not have to be added again by other users.
  1. Change your directory: 
      cd path/to/MORIS/
  2. Enter the command: 
      svn propset svn:ignore bin .
  3. To ignore files with a particular extension (say, all .pdf files), use the command: 
      svn proset svn:ignore *.pdf .
  4. Commit the project. This will commit changes to the directory properties.

CVS - SVN Differences

Taken from: Pushok Software's Comparison and various StackExchange threads:

CVS SVN
Repository Format Files and directory format as expected, files are standard format that contain extra info Funny database format, need special tools (which are easily available)
File Types Primarily intended for text files, binary files not necessarily handled well Handles all well
Rollback Can roll back any commit Bad commit will remain, will need to either dump repository history before commit and recreate with that history or use old version to change
Committing Can have half your commit work and half fail, so repo is in broken state All goes or nothing goes
Version Renaming/Moving Cannot happen Can happen
Directory Handling Not included in versioning Normal operation of repository
