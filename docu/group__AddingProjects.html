Adding a new project to moris clearly takes a lot of code, and the CMake is no exception. Fortunately, it's not terribly complicated. We've split the instructions into three sections: Upper-Level Edits, Project-Level CMakeLists, and Config.

Upper-Level Edits

Below is the minimum information needed to complete the upper-level edits for your project. For a more detailed explanation of what each part of the code is doing, refer to Upper-Level Code Details.

Top-level CMakeLists.txt

First, open the CMakeLists.txt file in the top level moris directory. 

cd $HOME/codes/moris
kwrite CMakeLists.txt

In the CMake file, create a variable for your project under the moris Directories section. It should be a three letter abbreviation of your project's name. Follow the example of the other entries in this section. 

# Source Directories
set(ALG "ALG")

Scroll down to the @type{Package Options} section and add an option to build your project. The default behavior of this option should be OFF. 

option(BUILD_ALG "Build the algorithms library and executable." OFF)

Toward the bottom of the file, find the @type{Depends files} section. Here, add an if statement and include command for your project. 

if(BUILD_ALG)
    include(${MORIS_DEPENDS_DIR}/ALG_Depends.cmake)
endif()

Utilities

Exit the top-level CMakeLists.txt and move into share/cmake/utilities. Here, open build_all_exe.cmake. 

cd share/cmake/utilities
kwrite build_all_exe.cmake

In this file, add a line setting your project's build option to ON. 

set(BUILD_ALG ON CACHE BOOL "Build the algorithms library and executable." FORCE)

Dependency file

Next, go into the dependency file directory, share/cmake/depends, and create a new file. Its name should be your project's three-letter abbreviation followed by _Depends.cmake. From the utilities directory, 

cd ../depends
kwrite ALG_Depends.cmake

Copy and paste the following into your project's new depends file: 

# proj Dependencies -------------------------------------------------------
# -------------------------------------------------------------------------

# Check if PROJ has already been included
if(DEFINED PROJ_CONFIGURED_ONCE)
    return()
endif()

set(PROJ_CONFIGURED_ONCE "YES")

# - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - -
# Handle Dependencies

# Add PROJ to the source directory list
list(APPEND MORIS_SOURCE_DIRS ${PROJ})

# Include third party libraries directly needed by PROJ
set(PROJ_TPL_DEPENDENCIES
    "viennacl"
    ${ARMADILLO_EIGEN} )

# List moris projects directly needed by PROJ
set(PROJ_MORIS_DEPENDENCIES
    ${LNA} )

foreach(MORIS_DEPENDENCY ${PROJ_MORIS_DEPENDENCIES})
    # Include moris projects directly needed by PROJ
    include(${MORIS_DEPENDS_DIR}/${MORIS_DEPENDENCY}_Depends.cmake)

    # Include third party libraries indirectly needed by PROJ
    list(APPEND PROJ_TPL_DEPENDENCIES ${${MORIS_DEPENDENCY}_TPL_DEPENDENCIES} )
endforeach()
  1. Replace all instances of "proj" with the full name of your project and all instances of "PROJ" with the abbreviated name of your project.
    • For example, ALG is the abbreviated name of the project whose full name is Algorithms (DLA is Distributed Linear Algebra, etc).
    • In KWrite and most other IDEs, this can be quickly done using a find and replace command (Ctrl + R or Ctrl + F in most platforms).
  2. List any third party libraries that your project files use under your project's list of TPL_DEPENDENCIES.
    • These are lowercase library names in quotes, such as "viennacl".
    • For third party libraries where one or another can be used for the same purpose, dereference the appropriate library variable.
      • These variables are named as an underscore-separated list of the libraries in alphabetical order.
      • At the time of writing, the only variables like this are ARMADILLO_EIGEN and ACML_LAPACK_MKL.
  3. List other moris projects that your project depends on under your project's list of MORIS_DEPENDENCIES.

Project-Level CMakeLists

Once the Upper-Level Edits have been made, CMakeLists.txt files have to be added to your project's directory tree. This section will give you only what you need to complete the CMake code. For a more detailed look at what each part of the code does, refer to Project-Level CMakeLists Details.

Project Top-Level CMakeLists.txt

Go to your project's top directory and create a CMakeLists.txt file. 

cd $HOME/codes/moris/projects/PROJ
kwrite CMakeLists.txt

Copy and paste the following template into this file: 

# proj --------------------------------------------------------------------
# -------------------------------------------------------------------------

# Third party library dependencies
list(REMOVE_DUPLICATES PROJ_TPL_DEPENDENCIES)
foreach(PROJ_TPL ${PROJ_TPL_DEPENDENCIES})
    include(${MORIS_CMAKE_DIR}/${PROJ_TPL}.cmake)
endforeach()

# Add source directory
add_subdirectory(src)

# Add test directory
if(MORIS_USE_TESTS AND BUILD_PROJ)
    add_subdirectory(test)
endif()
  1. Replace all instances of "proj" with the full name of your project (eg. algorithms) and all instances of "PROJ" with the abbreviated name of your project (eg. ALG).

Source-Level CMakeLists.txt

After the top-level project CMakeLists file is created, move into the src directory and open a CMakeLists.txt file there. 

cd src
kwrite CMakeLists.txt

Header Section

At the top of this file, paste the following code: 

# proj --------------------------------------------------------------------
# -------------------------------------------------------------------------

# Set version
set(${PROJ}_VERSION ${MORIS_VERSION})

# List header files
set(HEADERS
    project_header_1.hpp
    ...
    project_header_n.hpp )

# List header dependencies
set(PROJ_INCLUDES
    ${MORIS_PROJECT_1}
    ...
    ${MORIS_PROJECT_N} )

foreach(PROJ_INCLUDE ${PROJ_INCLUDES})
    include_directories(../../${PROJ_INCLUDE}/src)
endforeach()
  1. Replace all instances of "proj" with the full name of your project (eg. algorithms) and all instances of "PROJ" with the abbreviated name of your project (eg. ALG).
  2. List your project's header files under the HEADERS variable.
    1. This can be done easily by typing @type{ls -1 *.hpp} in the command line and then copying the output into the list.
  3. List the moris projects that your project includes in the _INCLUDES variable.
    1. Nested projects like FEM/INT and FEM/MSI need to be listed fully (i.e. ${FEM}/${INT}, not just ${INT}).

Library and Executable sections

For these sections, refer to Adding Libraries and Adding Executables.

Config File and Installation Sections

Paste the following after the Library and Executable sections: 

# - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - -
# proj Config Files

# Build *Config and *ConfigVersion files
include(CMakePackageConfigHelpers)

configure_package_config_file(
    ${PROJ}Config.cmake.in
    ${${PROJ}_CONFIG_BUILD_DIR}/${PROJ}Config.cmake
    INSTALL_DESTINATION ${CONFIG_INSTALL_DIR}/${PROJ}
    PATH_VARS LIB_INSTALL_DIR )

write_basic_package_version_file(
    ${${PROJ}_CONFIG_BUILD_DIR}/${PROJ}ConfigVersion.cmake
    VERSION ${{PROJ}_VERSION}
    COMPATIBILITY AnyNewerVersion )

# - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - -
# proj Installation

# Install *Config and *ConfigVersion files
install(FILES ${${PROJ}_CONFIG_BUILD_DIR}/${PROJ}Config.cmake 
    ${${PROJ}_CONFIG_BUILD_DIR}/${PROJ}ConfigVersion.cmake
    DESTINATION ${CONFIG_INSTALL_DIR}/${PROJ} )

# Install header files
install(FILES ${HEADERS}
    DESTINATION ${HEADER_INSTALL_DIR}/${PROJ} )

# Install library and executable
install(TARGETS ${PROJ}-lib ${PROJ}-exe
    ARCHIVE_DESTINATION ${LIB_INSTALL_DIR}/${PROJ}
    LIBRARY_DESTINATION ${LIB_INSTALL_DIR}/${PROJ}
    RUNTIME_DESTINATION ${EXE_INSTALL_DIR}/${PROJ}
    EXPORT ${PROJ}Targets )

# Export library into *Targets file
install(EXPORT ${PROJ}Targets
    DESTINATION ${CONFIG_INSTALL_DIR}/${PROJ} )
  1. Replace all instances of "proj" with the full name of your project (eg. algorithms) and all instances of "PROJ" with the abbreviated name of your project (eg. ALG).
    1. Note that the @type{install(TARGETS...} command will throw an error if the targets listed do not exist. If no executable is created for your project, remove ${PROJ}-exe. Likewise, if no library is created for your project, remove ${PROJ}-lib.

Test-Level CMakeLists.txt

The CMakeLists.txt file in the test directory should take the following form: 

# proj Tests --------------------------------------------------------------
# -------------------------------------------------------------------------

# List source files
set(TEST_SOURCES
    test_main.cpp
    my_test_1.cpp
    ...
    my_test_n.cpp )

# List test includes
set(TEST_INCLUDES
    ${LNA}
    ${IOS}
    ${COM}
    ...
    ${MORIS_PROJECT} )

foreach(TEST_INCLUDE ${TEST_INCLUDES})
    include_directories(../../${TEST_INCLUDE}/src)
endforeach()

# List additional includes

# List test dependencies
set(TEST_DEPENDENCIES
    ${COM}-lib
    ...
    ${MORIS_{TPL}_LIBS} )

# Set the output path for test
set(CMAKE_RUNTIME_OUTPUT_DIRECTORY ${CMAKE_CURRENT_BINARY_DIR}/${BIN})

# Create executable
add_executable(${PROJ}-test${EXE_EXT} ${TEST_SOURCES})
target_link_libraries(${PROJ}-test${EXE_EXT} ${TEST_DEPENDENCIES})

# Mark as test
add_test(NAME ${PROJ}-test
    COMMAND ${PROJ}-test${EXE_EXT} )
  1. Replace all instances of "proj" with the full name of your project (eg. algorithms) and all instances of "PROJ" with the abbreviated name of your project (eg. ALG).
  2. List your source test files in the TEST_SOURCE variable.
    1. This can be quickly done by copying and pasting the output from running @type{ls -1 *.cpp} in the command line.
    2. The first file in this list should always be test_main.cpp.
      1. test_main.cpp can be found in any other moris project's test directory.
  3. List the moris projects your test files include in the TEST_INCLUDES variable.
    1. There may be more projects to include when building the tests than when building the library for a project.
    2. test_main.cpp requires header files from ${LNA}, ${IOS}, and ${COM} so these will always need to be included for tests.
  4. List libraries the test needs to link to under the TEST_DEPENDENCIES variable.
    1. Libraries from moris projects are a project's abbreviation followed by -lib.
    2. Third party libraries should be dereferenced from MORIS_TPL_LIBS variables where TPL is the name of the appropriate third party library (e.g. MORIS_SUPERLU_LIBS).
      1. For supported third party libraries that serve the same purpose, replace TPL with all of those libraries, in caps and separated by underscores (e.g. MORIS_ACML_LAPACK_MKL_LIBS).

Config

The config file is the last CMake file needed to integrate your project into moris. For a detailed look at the lines of code provided below, refer to ExplainConfig. In the src directory, create a file named with your project abbreviation followed by Config.cmake.in. 

cd ../src
kwrite PROJConfig.cmake.in

In the file, paste the following code: 

# proj Config File --------------------------------------------------------
# -------------------------------------------------------------------------

# - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - -
# CMake configuration

@PACKAGE_INIT@

# - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - -
# MORIS configuration

# Set *_INCLUDE_DIRS
set_and_check(@PROJ@_INCLUDE_DIRS @PACKAGE_LIB_INSTALL_DIR@/@PROJ@)

# Create PROJ targets
include(@PROJ@Targets.cmake)
  1. Replace all instances of "proj" with the full name of your project (eg. algorithms) and all instances of "PROJ" with the abbreviated name of your project (eg. ALG).

Note that this file is used to provide users with what information (mostly paths and the like) moris uses when compiling. Any relevant information along these lines should be added with the steps listed in ExplainConfig.
