How to "install" MORIS?

Instructions on how to Checkout MORIS and Checkout the MTPLS Folder are included below. If you have already done this, you may skip to Compile the Code.

Checkout MORIS

You may Checkout Using Eclipse or Checkout Using the Terminal.

Checkout Using Eclipse

Checking out the code in Eclipse requires an SVN plug-in; if you have not already installed it, refer to section: Installing the SVN Plug-In. To import the project in Eclipse,

  1. Open the New Project Wizard, either:
    • Click on File and click on @bold{New > Project...}
      OR
    • Right-Click inside the Project Brower and select @bold{New > Project...}
  2. Expand the SVN folder and select @bold{Project from SVN}. Click Next.
  3. In the URL field, enter: svn+ssh://thunderbird.colorado.edu/home/svnroot/MORIS
  4. In the Authentication section, enter your Thunderbird username and password. It is recommended that you choose the Save authentication option. Click Next.
  5. The Head Revision is chosen by default. You may choose a version by date or by browsing past revisions. Click Finish.
  6. Leave the Depth option as Recursively. Click Next.

  7. Eclipse will checkout the project in the default workspace. You may choose to specify a custom location. It is strongly recommended to have your code in

    $HOME/codes

Click Finish.

  1. If you chose to save your authentication information, you may be prompted to provide security questions and answers. You may opt out or click Yes to provide your custom security information. After you have done so, click Ok.

Checkout Using the Terminal

To checkout via a command window, you will need to have Subversion installed on your machine. This requires root access (contact Kurt first). Move to a desired directory, for example: 

cd $HOME/codes

Then, enter the command: 

svn checkout svn+ssh://thunderbird.colorado.edu/home/svnroot/MORIS

You may be prompted to enter your password.

Checkout the MTPLS Folder

In addition to checking out the MORIS, you will also need to have a link to a directory with third party libraries used in moris. Move to your home directory and run the command: 

cd
ln -s /home/maute/tpls .

Included are the arma and eigen folders, which contain the Armadillo and Eigen libraries, among others. If a link called tpls already exists, remove the link first.

Finally, moris needs to be able to find the superlu, petsc, and boost folders. This is done by setting the locations of these libraries as environment variables. In .cshrc files, add the lines: 

# SuperLU
setenv SUPERLUDIR $HOME/tpls/SuperLU/gcc-openmpi/

# PETSC
setenv PETSC_DIR $HOME/tpls/petsc/gcc-openmpi

# BOOST
setenv BOOST_ROOT $HOME/tpls/boost
setenv LD_LIBRARY_PATH $HOME/tpls/boost/lib/:$LD_LIBRARY_PATH/

Alternatively, for .bashrc files, add the lines: 

# set SUPERLU
export SUPERLUDIR=$HOME/tpls/superlu

# set PETSC
export PETSC_DIR=$HOME/tpls/petsc

# BOOST
export BOOST_ROOT=$HOME/tpls/boost
export LD_LIBRARY_PATH=$HOME/tpls/boost/lib/:$LD_LIBRARY_PATH/

Note that the lines lead with # are comments for convenience and may be omitted.

Setting MORISROOT as an Evironmental Variable

In order to read external files in MORIS, all paths are specified with respect to MORISROOT. Therefore, intially the loaction of the MORIS directory needs to be specified by defining MOORISROOT as an environmental variable. In .cshrc files, add the lines: 

# set MORISROOT
setenv MORISROOT $HOME/codes/MORIS

Alternatively, for .bashrc files, add the lines: 

# set MORISROOT
export MORISROOT=$HOME/codes/MORIS

Note that the lines lead with # are comments for convenience and may be omitted.

Compile the Code

This project uses a makefile wrapper to handle all of the compiling; for a detailed discussion on this matter, see The Makefile Wrapper section.

To compile the project, move into the MORIS directory after checking it out and perform the following steps: 

cd $MORISROOT
mkdir build
cd build
cmake ..
ccmake .
make

See ccmake Options for compiling options. Many users will choose to stipulate the type of build (debug or optimized) in the folder name. For example commonly used names are build_dbg and build_opt.

It is strongly recommended to create a separate build directory for each compile configureation. Compile configurations differ by the BLAS and LAPACK libraries used, the optimization level, and which linear algebra package (i.e. Armadillo or Eigen) is used.

Standard compile configurations are:

  • Non-optimized BLAS/LAPACK – Armadillo – debug option: 
      cd $MORISROOT
  mkdir build-blas-arma-dbg
  cd build-blas-arma-dbg
  cmake -D MORIS_USE_ARMA:STRING=ON -D MORIS_USE_ACML:STRING=OFF -D MORIS_USE_BLAS:STRING=ON -D MORIS_HAVE_DEBUG:STRING=ON ..
  • Non-optimized BLAS/LAPACK – Eigen – debug option: 
      cd $MORISROOT
  mkdir build-blas-eigen-dbg
  cd build-blas-eigen-dbg
  cmake -D MORIS_USE_ARMA:STRING=OFF -D MORIS_USE_EIGEN:STRING=ON -D MORIS_USE_ACML:STRING=OFF -D MORIS_USE_BLAS:STRING=ON -D MORIS_HAVE_DEBUG:STRING=ON ..
  • Optimized BLAS/LAPACK (ACML) – Armadillo – no-debug option: 
      cd $MORISROOT
  mkdir build-acml-arma-opt
  cd build-acml-arma-opt
  cmake -D MORIS_USE_ARMA:STRING=ON -D MORIS_USE_ACML:STRING=ON -D MORIS_USE_BLAS:STRING=OFF -D MORIS_HAVE_DEBUG:STRING=OFF ..
  • Optimized BLAS/LAPACK (ACML) – Eigen – no-debug option: 
      cd $MORISROOT
  mkdir build-acml-eigen-opt
  cd build-acml-egien-opt
  cmake -D MORIS_USE_ARMA:STRING=OFF -D MORIS_USE_EIGEN:STRING=ON -D MORIS_USE_ACML:STRING=ON  -D MORIS_USE_BLAS:STRING=OFF -D MORIS_HAVE_DEBUG:STRING=OFF ..
    Everytime a new library is linked to MORIS, the build directory needs to be deleted. Same needs to be done if any of the cmake files were changed.

To clean the code (whenever a .hpp or .tpp file is changed), use the clean target: 

cd $MORISROOT/build
make clean

To clean and build MORIS via Eclipse,

  1. Right click on the project MORIS and click on Properties.
  2. Go to the @bold{C/C++ Build} tab and set the @bold{Build directory} to path/to/MORIS.
  3. Under the Behavior tab set the @bold{clean target to distclean}.

ccmake Options

The compile options can be stipulated with the ccmake . command. This command will take the into an interactive environment that allows them enable or disable different options. The following image shows an example for a debug compile configuration.

Figure: example ccmake options for a debug build

A standard opt version usually sets the following options to OFF in the ccmake interactive window: BUILD_EXA, MORIS_HAVE_DEBUG, MORIS_HAVE_SYMBOLIC, MORIS_USE_EXAMPLES, and MORIS_USE_TESTS.

Running Doxygen

Assuming you have doxygen installed on your local machine, move into the MORIS main directory and run the doxygen command: 

cd $MORISROOT
make doxy

You may now open doc/doxygen/html/index.html in an internet browser. To do this from a terminal using firefox, use the command: 

firefox doc/doxygen/html/index.html &

Doxygen gathers any warnings and errors in the file: warn_log_doxy.txt in the MORIS directory. Typical errors include misused doxygen warnings and incorrect paths to code snippets (see Documentation Style).

Cleaning Doxygen

To clean the Doxygen output, use the command: 

cd $MORISROOT
make doxyclean

Installing Doxygen

Doxygen has a binary distribution for Linux available for download. After downloading the executable, add the location to the PATH variable in the .cshrc or .bashrc file.

Preferences

To maintain a level of uniformity, it is recommended that you use the Eclipse preferences that are part of the project.

Importing

To import the group's Eclipse preferences,

  1. Open the File menu and click on Import.
  2. Expand the General folder and select Preferences. Click Next.
  3. Click Browse next to the dropdown menu and navigate to MORIS/share/eclipse/.
  4. Select eclipse_preferences.epf and click Open.
  5. Check the box next to Import All and click Finish.

Exporting

To export your Eclipse preferences,

  1. Open the File menu and click on Export.
  2. Expand the General folder and select Preferences. Click Next.
  3. Click Browse next to the dropdown menu and navigate to MORIS/share/eclipse/.
  4. If it already exists, select eclipse_preferences.epf to overwrite it. Otherwise, type a custom name. Click Finish.
  5. If overwriting, Eclipse will display an overwrite warning. Click Yes.
  6. Commit your preferences.
