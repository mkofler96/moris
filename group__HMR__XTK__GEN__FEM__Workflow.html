This section details functioning of HMR-XTK-GEN-FEM workflow in MORIS. It shows functional utility of each module as a part of workflow and how each module
interacts/communicates with each other starting from generating background mesh till creating a global assembly of system of equations for IQIs in FEM Module.
This workflow is particularly suited for multi-phase problem where boundary interface between two material phase requires mesh decomposition through XTK module.

Workflow-Performance

Each workflow, including the current workflow, performs in 3 stages. First stage sets up various performers (i.e, HMR_Performer, XTK_Performer etc.,). Second stage initialize the ADVs and third stage actually performs. Various performers are called through performer_manager.

Initializer:

Initialize module initializes ADVs bounded by upper and lower bounds from GEN. As shown in the figure above, initialize module consists of three performers, HMR,
MTK and GEN. HMR creates a background mesh and pass it to MTK Performer which stores MTK mesh. MTK Performer will pass this mesh to GEN and XTK. GEN takes MTK mesh and
evaluates level set field and other geometry parameters which will be used later by XTK and other modules.
In summary, for any FEM problem, HMR mesh and design variables (ADVs) are created once in the initialize module.

Call to HMR Mesh: mPerformerManager->mHMRPerformer( 0 )->perform();

Call to Design variables using GEN: mPerformerManager->mGENPerformer( 0 )->distribute_advs(mPerformerManager->mMTKPerformer( 0 )->get_mesh_pair( 0 ),tFieldsOut );

Performer:

Performer module begins from taking HMR Mesh stored in MTK as MTK Mesh. Then, XTK Performer is set to GEN Performer and MTK performer and build a new MTK mesh.
After this, XTK performs decomposition and enrichment and stores the mesh as MTK Mesh. Here, if decomposition performer can be performed, it deletes older XTK mesh
to free memory. At the decomposition stage, it computes intersection and if intersection exists it calls GEN to register intersection points.
Then, it constructs a database performer which stores MTK mesh and pass it to MDL.
See figure below to understand XTK performer.

Working of XTK Performer


MDL performer consists of MSI and SOL. It analyse the model as a part of forward analysis and solvess the physics problem. Then, a design variable interface is
set-up between GEN and MDL to pass IQIs from MDL to GEN.

Two mini performers are called in for remeshing and refinement depending on the criteria set.
1. Refinement Mini-performer: Refinement mini-performer takes GEN as criteria and HMR mesh as input to perform mesh refinement. Although it operates through
HMR-MTK-GEN workflow.

2. Remeshing Mini-performer: Remeshing is done based on certain requirements.
(1) If a criteria for number of iterations is met, or,
(2) If XTK or MDL asks to Remeshing.
If remeshing is done for analysis mesh, it is done at MTK-XTK stage. Here, the design mesh stays the same.
If remeshing is done for design mesh, it is done on HMR mesh since it requires new ADVs to be generated in GEN.

Constraints: Constraints refer to the criterias that trigger inter-calling between HMR, XTK, and GEN.
(1). XTK --> GEN : XTK calls GEN at the decomposition stage to get computed geometry at each level-set field.
(2). HMR --> GEN : HMR interacts with GEN through MTK. While performing refinement, refinement mini-performer takes HMR with GEN as critieria.
