Bugzilla Installation, Setup, and Procedures

Installation

  1. Go to Help > Install New Software...
  2. Click on the dropdown menu and select –All Available Sites–.
  3. Expand the Collaboration section.
  4. Select the Mylyn Tasks Connector: Bugzilla.
  5. Click Next.
  6. Review the selection. Click Next.
  7. Accept the User Agreement.
  8. Click Finish.
  9. If prompted to restart Eclipse, do so.

Setting up the Bugzilla repository

  1. Go to Window > Show View.
  2. Select Task Lists.
  3. Go to Window > Show View > Other...
  4. Expand the Mylyn folder.
  5. Select Task Repositories.
  6. Click Ok.
  7. Right-click inside this view, select Add Task Repository.
  8. Select Bugzilla. If you have no other connectors install, it may already be selected.
  9. Click Next.
  10. If you have previously saved passwords with Eclipse, you may be prompted to enter your master password.
  11. In the Server field, enter: http://thunderbird.colorado.edu/bugzilla.
  12. In thte Label field, enter: moris tasks.
  13. Unselected the Anonymous check-box.
  14. Enter your Bugzilla User ID and Password. These are the same as the ones you use on the browser-based version of Bugzilla.
  15. You may opt into saving your password. If you have never done this, Eclipse will then prompt you to set up a master password and secuity questions.
  16. Click Finish.
  17. If prompted to set up a query, choose Yes if you haven't set up a query for this repository. Otherwise, choose No.

Setting up a Bugzilla Query

  1. In the Task List view, right-click in an emtpy area.
  2. Go to New and select Query.
  3. Select the moris bugzilla repository: "moris tasks".
  4. Click Next.
  5. Click Next.
  6. In the Title field, enter: moris tasks query.
  7. Leave the Summary and Email fields blank.
  8. Select all options under Product, Component, Status, and Severity.
    • Select the first option.
    • Hold Shift and select the last option.
  9. Click Finish.
  10. Expand the moris tasks query in the Task List view to view all reported bugs and tasks.
  11. Right click on the tasks query.
  12. Verify that Synchronize Automatically is checked.
    • If it does not appear, click on Synchroize.
    • Check that Syncronize Automatically appears as an option.

Making a Task

  1. Create a New Task:
    • Option #1:
      1. In the Task List view, right-click in an empty area.
      2. Click on New > Task.
      3. Select the moris tasks repository.
      4. Click Finish.
    • Option #2:
      1. In the Task List view, click on the New Task button.
      2. Select the moris tasks repository.
      3. Click Finish.
    • Option #3:
      1. In the task Repositories view, rightc-lick on moris tasks.
      2. Click on New Task.
  2. In the top field, enter the title of the bug or task.
  3. If needed, expand the Attributes section.
  4. Select the appropriate Component, Severity, and Priority.
  5. If needed, expand the Private section.
  6. If appropriate, enter a Due date.
  7. If needed, enter an Estimate number of hours that will fix will require.
  8. Enter a Description of the bug or task.
  9. If needed, expand the People section.
  10. Enter ther e-mail of the Assignee.
  11. Click Submit.

Responding to a Task

  1. Double-click on a task to open it.
  2. Typically, you will not need to make changes in the Attributes or Private sections. You cannot make changes to the Description.
  3. You may enter a new comment in the Comment section. If you would to reply to a previous comment, click the Reply button.
  4. If needed, expand the Actions section.
  5. As appropriate, change the status of the bug or task. See Status of a bug.
  6. Click Submit.

For more, visit https://developer.mozilla.org/en-US/docs/What_to_do_and_what_not_to_do_in_Bugzilla#Resolving_bugs.

Status of a bug

The life cycle of a bug is as follows:

  1. UNCONFIRMED: The bug has been reported and is awaiting confirmation
  2. CONFIRMED: The bug has been confirmed by a second user
  3. STARTED/IN PROGRESS: Assignee has started working on the bug/task
  4. Resolved as FIXED: Assignee has fixed the bug or finished the task
  5. Resolved as INVALID: Bug report is vague or illegible (uncommon)
  6. Resolved as WORKSFORME: Bug cannot be reproduced (uncommon)
  7. Resolved as WONTFIX: Covers all other reasons why bug will not be worked (obsolete component, for example)
  8. Duplicate of another bug (uncommon)
  9. VERIFIED: Fix for a bug has been verified by someone other than the assignee (Bugzilla does not support this, but it is a common status in other bug reporting platforms)

Notes

  • When a new task is assigned or other changes are made, a pop-up notification will appear once Eclipse synchronizes with the repository.
  • You may create a task from a marker in the Problem view or a FixMe/ToDo item in the Task View by right-clicking the item and choosing New Task from Marker.... The file and line number will automatically populate the Description. A title for the bug will also be automatically generated.
